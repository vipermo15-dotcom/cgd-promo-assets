# 에이전트 오케스트레이션 설계 서식 (빈 양식)

에이전트 일기 번외에서 쓴 틀입니다. 자유롭게 복사해서 쓰세요.

## 1. 길 나누기
에이전트를 한 줄로 잇지 않고, 다루는 데이터가 다른 길로 나눕니다.

| 길 | 순서 | 사람이 확인하는 곳 |
|---|---|---|
| A | | |
| B | | |
| C (독립) | | |

- 길이 만나는 곳은 가능한 한 한 곳으로 줄입니다. 그곳이 가장 중요한 인계 지점입니다.

## 2. 원칙 (고쳐 써도 됩니다)
1. 에이전트끼리 직접 호출하지 않고, 파일(또는 승인된 데이터)로만 넘긴다.
2. 데이터 종류마다 단일 출처를 정한다(같은 일을 두 곳에서 하지 않는다).
3. 승인·게시·외부 쓰기는 오케스트레이터(허브)도 하지 않는다. 사람이 한다.
4. 외부 앱에는 직접 쓰지 않고, 내보내기 파일을 사람이 반입한다.

## 3. 인계 계약 (넘길 때 반드시 갖출 것)
| 넘기는 것 | 필수 항목 | 없으면 |
|---|---|---|
| | | 넘기지 않고 사유를 남긴다 |

## 4. 입구 검사
- 검사만 하고 고치거나 승인하지 않는다.
- 통과하지 못한 항목은 하류로 넘기지 않고 이유와 함께 남긴다.
- 검사가 확인하지 못하는 항목은 "확인하지 못함"으로 적는다.

## 5. 시험
- 먼저 가상 데이터로 시험한다(동의 없음, 철회, 만료 같은 거부 사례 포함).
- 실제 데이터는 소속 기관의 확인 뒤에 쓴다.
- 모델이 판단하는 부분은 시험한 사람과 만든 사람이 같지 않게 한다.
